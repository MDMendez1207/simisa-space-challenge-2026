# Contributing to SIMISA

Thank you for helping build SIMISA during NASA Space Apps Challenge 2026.

## Working agreement

1. Keep the main demo reproducible and usable without external APIs.
2. Map every functional body region to a metric that the system actually contains.
3. Distinguish clearly between implemented, simulated, and planned behavior.
4. Do not add diagnostic claims, treatment instructions, or clinical thresholds without an identified source and review by the team member responsible for medical content.
5. Record the origin, license, and modifications of every external asset.
6. Do not commit personal health data, credentials, private reference images, or local configuration.

## Branches and commits

- Create a short branch for each focused change, such as `feat/body-navigation` or `docs/demo-script`.
- Write clear commit messages in the imperative mood.
- Keep unrelated changes in separate commits.
- Pull the latest `main` before integrating shared work.

Suggested commit prefixes: `feat`, `fix`, `docs`, `design`, `refactor`, `test`, and `chore`.

## Pull requests

Describe:

- What changed and why.
- Which behavior is implemented or simulated.
- How the change was tested.
- Any new source, asset, license, or medical-content consideration.
- Screenshots or a short recording for visible interface changes.

## Before requesting review

- Open the body explorer and complete its core navigation.
- Test at the laptop resolution used for the presentation.
- Test keyboard navigation and reduced motion when the change affects interaction.
- Confirm that generated files, credentials, and private references are not staged.
- Update the relevant documentation.

## Language

User-facing application text and submission material should be written in English. Internal planning can remain in Spanish while the team works.
